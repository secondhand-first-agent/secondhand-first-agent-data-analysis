# 배송비 스코어링 규칙 검토

직거래 이동비용을 0으로 고정하는 방안을 실제 크롤링 데이터에 적용해 본 결과다.

**결론부터** — 규칙 자체는 근거가 있다. 다만 조건 하나가 빠져 있어
직거래 상품이 구조적으로 유리해진다. `min()` 계산은 그대로 두고
**거리 조건만 붙이면** 해결된다.

---

## 1. 검토한 규칙

```
직거래 이동비용 = 0 (고정)
배송비 = min(택배 최소비, 직거래 비용)
총 지불액 = price + 배송비
```

**이 방식의 정당한 근거** — 직거래는 현금 지출이 실제로 0원이다.
이동비용을 임의의 숫자로 정하는 것보다 정직하고, 계산도 단순하다.

---

## 2. 표본

통합 크롤러로 6개 검색어(닌텐도 스위치 OLED · 아이패드 에어 · 자전거 ·
책상 · 캠핑의자 · 캠핑 의자)를 수집한 **140건**이다.

| 구분 | 건수 |
| --- | ---: |
| 중고 (번개장터 · 중고나라 · N플리마켓) | 105 |
| 새상품 (11번가) | 35 |

---

## 3. 규칙을 적용하면 벌어지는 일

### 3-1. 배송비가 0이 되는 항목이 절반이다

직거래가 가능한 상품은 **72건 / 140건**이다. 이 규칙에서는 전부 배송비 0원이 된다.

| 구분 | 직거래 가능 | 비율 |
| --- | ---: | ---: |
| 중고 | **72 / 105** | 69% |
| 새상품 | **0 / 35** | 0% |

**새상품은 직거래가 하나도 없다.** 11번가는 오픈마켓이라 구조적으로
직거래가 존재하지 않는다. 즉 이 규칙은 결과적으로 **중고에만 적용되는
배송비 할인**이 된다.

### 3-2. 배송비 정보가 없는 항목이 최고점을 받는다

**직거래 전용 상품이 28건** 있다. 판매자가 택배를 받지 않는 글이라
통합 스키마에서 `delivery_fee.status`가 `NOT_AVAILABLE`이다.

이 규칙에서는 28건이 전부 **0원**, 즉 가능한 최선의 값을 받는다.

```
NOT_AVAILABLE (배송비를 모른다)  →  0원 (배송비가 없다)
```

정보가 가장 적은 항목이 순위에서 가장 앞으로 나온다.

### 3-3. 큰 택배비가 사라진다

직거래와 택배가 **둘 다 가능한 상품이 34건**, 그중 택배비가 0원이 아닌
것이 **23건**이다. 이 23건의 택배비가 0으로 덮인다.

| 통계 | 금액 |
| --- | ---: |
| 중앙값 | 5,000원 |
| 평균 | 13,383원 |
| 최대 | **60,000원** |
| 1만원 이상 | 8건 |

대부분은 5천원 수준이지만 부피가 큰 물건에서 크게 벌어진다.

| 택배비 | 판매가 | 지역 | 상품 |
| ---: | ---: | --- | --- |
| 60,000원 | 140,000원 | 경기 남양주 | 퍼시스 책상 + 서랍장 세트 |
| 50,000원 | 300,000원 | 경기 남양주 | 퍼시스 인에이블 책상 세트 |
| 35,000원 | 190,000원 | 경기 남양주 | 일룸데스커 1600 책상 |
| 30,000원 | 1,400,000원 | 경기 용인 | 커넥티드 전기자전거 |

부산 사용자에게 남양주 책상이 **"배송비 0원"** 으로 표시된다.
실제로는 택배로 6만원이거나, 직접 남양주까지 가야 한다.

### 3-4. 동점이 대량으로 생긴다

배송비가 전부 0으로 눌리면 판매가가 같은 상품의 총액이 같아진다.

| 검색어 | 총액 계산 가능 | 동점 발생 |
| --- | ---: | ---: |
| 아이패드 에어 | 20건 | **7건** |
| 책상 | 32건 | **8건** |
| 캠핑 의자 | 24건 | **7건** |
| 캠핑의자 | 20건 | 6건 |
| 닌텐도 스위치 OLED | 12건 | 2건 |
| 자전거 | 32건 | 2건 |

동점을 무엇으로 가를지 정해야 한다.

### 3-5. 카카오맵 거리 기능이 총액에 반영되지 않는다

지금 거리 계산 기능을 별도로 만들고 있는데, 이동비용을 0으로 고정하면
**그 값이 총 지불액에 들어갈 자리가 없다.** 두 작업이 서로 어긋난다.

---

## 4. 제안 — 조건 하나만 추가

`min()` 구조와 "직거래는 0원"이라는 전제를 모두 유지한다.
**직거래 0원을 거리 조건을 통과한 경우에만 허용**하면 된다.

```
직거래비용 = 0        (거리 ≤ 임계값)
           = 후보 제외  (거리 > 임계값 또는 거리 미상)

배송비 = min(택배 최소비, 직거래비용)
```

바뀌는 것은 조건 하나지만 위 문제가 모두 해소된다.

| 상황 | 결과 |
| --- | --- |
| 판매자가 가깝다 | 직거래 0원이 그대로 이긴다 — 의도한 동작 |
| 판매자가 멀다 | 직거래가 빠지고 택배비로 돌아간다 (6만원이 6만원으로 보인다) |
| 직거래 전용인데 멀다 | **총액 계산 불가**. 0으로 채우지 않는다 |
| 총액이 동점이다 | 거리로 가른다. 이미 계산돼 있다 |

### 계산 불가는 순위에서 빼지 말 것

총액을 계산하지 못한 상품을 조용히 제외하면 사용자는 그 상품이
존재하지 않는 줄 안다. 별도로 보여주고 이유를 밝히는 편이 맞다.

### 결측값을 0으로 채우지 말 것

거리를 못 구했을 때 `null` 대신 0을 넣으면 **주소를 읽지 못한 상품이
"가장 가까운 상품"** 이 되어 추천 1위로 올라간다. 배송비도 같다.

---

## 5. 정해야 할 것

| 항목 | 내용 |
| --- | --- |
| **거리 임계값** | 직거래를 후보로 인정할 최대 거리. 지하철 이동권인 10~15km가 출발점이지만 근거가 약하니 팀에서 합의해 고정하고 이유를 기록한다 |
| **동점 처리** | 총액이 같을 때의 2차 정렬 기준. 거리 → 상품 상태 순을 권한다 |
| **편의점 배송 반영** | `delivery_fee.min_fee`(편의점 포함 최저)와 `home_delivery_fee`(편의점 없이) 중 무엇을 쓸지는 사용자 상황에 달렸다. 두 값을 나눠 둔 이유가 이것이다 |

---

## 6. 참고 — 왜 이 편향이 중요한가

기획서에 이렇게 적혀 있다.

> 거리를 빼고 비교하면 **"배송비 없음"인 직거래가 늘 유리해 보이는 편향**이 생긴다.

거리 조건을 넣으면 이 문장이 코드로 지켜진다.
