# 통합 스키마 정의

번개장터 / 중고나라 / N플리마켓 / 11번가 네 플랫폼의 크롤링 결과를 하나의 형태로 합친 스키마다.
앞의 셋은 중고, 11번가는 새상품 비교 기준이다.
`crawler/unified/transform_to_unified_schema.py`가 이 문서의 규칙대로 변환하고,
`crawler/unified/validate_unified_schema.py`가 규칙을 지켰는지 검사한다.

**설계 원칙** — 값이 없는 자리에 임의의 `0`·`false`·추정값을 채우지 않는다.
판단이 불가능하면 `null` 또는 `UNKNOWN`으로 남긴다.

## 2. 상품 가격 `price`

플랫폼 원본의 판매가를 그대로 담는다. **배송비는 포함하지 않는다.**

| 플랫폼 | 원본 경로 |
| --- | --- |
| 번개장터 | `common.price` |
| 중고나라 | `common.price` (JSON-LD `offers.price`) |
| N플리마켓 | `common.price` |

### 실제 데이터 (표본 40건)

| 상품군 | 최저 | 최고 |
| --- | --- | --- |
| 무료나눔 | **0원** | 20,000원 |
| 문화상품권 | 2,000원 | 11,111,111원 |
| 닌텐도 스위치 OLED | 34,000원 | 360,000원 |
| 냉장고 | 150,000원 | 900,000원 |
| 샤넬 가방 | 60,000원 | 4,300,000원 |

**`price: 0`은 정상값이다.** 무료나눔 게시글에서 실제로 3건 확인됐다.

> ⚠️ **이상치 주의** — `11,111,111원`은 `"문화상품권 개진상 악질 닉네임HH"`라는 저격 게시글이다.
> 판매 의사가 없는 더미 가격이며 크롤러 필터를 통과한다.
> 상품이 아닌 게시글 판별은 에이전트 Tool/프롬프트 단계에서 처리하기로 했다.

### 총 지불액

`price`에는 배송비가 없으므로 총 지불액은 아래처럼 계산한다.

```
총 지불액 = price + delivery_fee.min_fee            # 편의점 픽업 가능한 사용자
총 지불액 = price + delivery_fee.home_delivery_fee  # 픽업이 어려운 사용자
```

거래방식이 여러 개면 경우의 수가 갈리므로, Top-K 단계에서 조합별로 계산한 뒤
최종 순위를 정하는 방식을 쓴다.

## 3. 상품 상태 `condition_level`

### 통합 값 6종

| 값 | 의미 |
| --- | --- |
| `NEW` | 새것 |
| `LIKE_NEW` | 거의 새것 |
| `LIGHTLY_USED` | 사용감 적음 |
| `USED` | 중고 (사용감 많음 + 세분화 정보가 없는 경우) |
| `UNSPECIFIED` | 판매자가 상태 등급을 지정하지 않음 |
| `UNKNOWN` | 매핑되지 않는 값이거나 필드 자체가 없음 |

`UNSPECIFIED`(판매자가 안 적음)와 `UNKNOWN`(우리가 매핑 못 함)은 성격이 다르므로 구분한다.

### 플랫폼별 매핑

번개장터와 N플리마켓은 **4등급 체계가 같고 이름만 다르다.** 등급의 위치로 대응시킨다.

```
번개장터    NEW → LIKE_NEW   → LIGHTLY_USED → HEAVILY_USED
N플리마켓   NEW → ALMOST_NEW → USED         → HEAVILY_USED
```

| 플랫폼 | 원본값 | → `condition_level` |
| --- | --- | --- |
| 번개장터 | `NEW` | `NEW` |
| 번개장터 | `LIKE_NEW` | `LIKE_NEW` |
| 번개장터 | `LIGHTLY_USED` | `LIGHTLY_USED` |
| 번개장터 | `HEAVILY_USED` | `USED` |
| 번개장터 | `UNDEFINED` | `UNSPECIFIED` |
| N플리마켓 | `NEW` | `NEW` |
| N플리마켓 | `ALMOST_NEW` | `LIKE_NEW` |
| N플리마켓 | `USED` | `LIGHTLY_USED` |
| N플리마켓 | `HEAVILY_USED` | `USED` |
| 중고나라 | `0` | `NEW` |
| 중고나라 | `1` | `UNSPECIFIED` |
| 중고나라 | `2` | `USED` |
| 11번가 | `새상품` | `NEW` |
| 11번가 | `중고상품` | `USED` |
| 전 플랫폼 | 위에 없는 값 · 필드 누락 | `UNKNOWN` |

> **이름이 엇갈려 보이는 이유** — N플리마켓 원본 `USED`가 통합 `LIGHTLY_USED`가 되고,
> 원본 `HEAVILY_USED`가 통합 `USED`가 된다. 등급 위치로 대응시킨 결과이며 의도된 것이다.

> **`HEAVILY_USED` 통합** — 팀 논의 결과 `USED`로 합쳤다. 그 결과 통합 `USED`에는
> "사용감 많음"과 "중고나라처럼 세분화 정보가 없는 중고"가 함께 들어간다.
> 구분이 필요하면 `condition_raw`를 참조한다(`"HEAVILY_USED"` vs `"2"`).

### 11번가 상태값을 어디서 읽는가

11번가 **검색 API에는 상태 필드가 없다.** `itemCondition`은 표본 50건 전부 `null`이었다.
그래서 새상품 마켓이니 `NEW`로 고정하는 방안을 검토했지만, 실제로 중고가 섞여 있어
폐기했다(`중고 아이폰` 검색 시 `A등급 ... 중고폰 공기계`가 나온다).

상태는 **상품 상세 페이지의 `상품상태` 행**에서 읽는다. 표본 35건 전부 이 행이 있었다.

```html
<th scope='row'>상품상태</th><td>중고상품</td>
```

| 확인한 값 | 건수 |
| --- | --- |
| `새상품` | 31 |
| `중고상품` | 4 |

> **리퍼브는 별도 값이 아니다.** `리퍼 노트북`·`리퍼브 냉장고` 검색 결과도 `새상품`으로
> 나온다. 리퍼브를 구분하려면 다른 근거가 필요하다.

### 11번가 렌털 제외

11번가에는 렌털·구독 상품이 섞여 있고 **`상품상태`가 `새상품`으로 나온다.**
물건은 새것이지만 소유권을 사는 거래가 아니다. 월 구독료가 판매가로 읽히면
총 지불액 비교가 무너지므로 수집 단계에서 제외한다.

판별은 두 단계다.

| 단계 | 근거 | 값 |
| --- | --- | --- |
| 1. 검색 | `unitTxt` | `원/월`, `원~/월` → 렌털 |
| 2. 상세 | `categoryBadge` / `categoryPath` | `렌털` / `렌털/구독 서비스…` → 렌털 |

1단계에서 걸러 상세 요청을 아끼고, 놓친 것을 2단계에서 잡는다.

**검증 49건에서 오탐·누락 0건이었다.**

| 검사 | 표본 | 결과 |
| --- | --- | --- |
| `unitTxt`에 `/월` 있음 → 실제 렌털인가 | 18건 | 18건 모두 렌털 |
| `unitTxt`가 `원` → 렌털이 아닌가 | 31건 | 31건 모두 비렌털 |

제목의 "렌탈" 문자열로 거르면 안 된다. `정수기렌탈가격비교` 같은 검색어 낚시
제목을 단 일반 침대 상품이 대량으로 걸린다. `unitTxt`는 이것을 정확히 구분한다.

`--include-rental`을 주면 렌털도 수집한다. 향후 "빌리는 게 나은가" 판단에 쓸 수 있다.

### 중고나라 상태값을 어디서 읽는가

**JSON-LD의 `offers.itemCondition`은 쓸 수 없다.** 미개봉 상품까지 포함해
표본 22건 전부 `https://schema.org/UsedCondition`으로 고정되어 있다.

실제 값은 상세 페이지 내부 데이터에 따로 있다.

```json
"condition": {
  "productCondition": 0,
  "options": { "fullPackageYn": 0, "limitedEditionYn": 0, "flawedYn": 0 }
}
```

`0`=새상품 / `2`=중고는 화면의 '새상품'·'미개봉' 표기와 대조해 확정했다
(`미개봉` 검색 10건이 10/10 모두 `0` + '새상품' 표기).
`1`은 아직 관측되지 않아 `UNSPECIFIED`로 두고, 실제 값이 발견되면 재확인한다.

### 실제 분포 (표본 40건)

| `condition_level` | 건수 | 플랫폼 |
| --- | --- | --- |
| `LIGHTLY_USED` | 13 | 번개장터 7 · N플리마켓 6 |
| `USED` | 11 | 중고나라 11 |
| `LIKE_NEW` | 7 | 번개장터 3 · N플리마켓 4 |
| `NEW` | 6 | 번개장터 2 · 중고나라 4 |
| `UNSPECIFIED` | 3 | 번개장터 3 |

## 4. 배송비 `delivery_fee`

원본은 `raw`에 그대로 보존하되, 에이전트가 바로 쓸 수 있도록 **부담 주체**와
**대표 금액 두 개**, **정규화된 배송 수단 목록**을 함께 제공한다.

### 구조

```jsonc
{
  "status": "AVAILABLE" | "NOT_AVAILABLE",  // 배송비 정보를 알 수 있는가
  "payer":  "SELLER" | "BUYER" | null,      // 누가 부담하는가
  "min_fee": 2500,                          // 전체 최저 배송비
  "home_delivery_fee": 5000,                // 편의점 픽업이 필요 없는 수단 중 최저
  "options": [ /* 배송 수단별 상세 */ ],
  "raw": { /* 플랫폼 원본 그대로 */ }
}
```

**`min_fee`와 `home_delivery_fee`를 나눈 이유** — 편의점 택배(반값·알뜰)가 가장 싸지만
주변에 해당 편의점이 없는 사용자에게는 선택지가 아니다. 최저가만으로 비교하면
그런 사용자에게 실제보다 싸 보인다.

`home_delivery_fee`가 `null`이면 **편의점 픽업 외 배송 수단이 없다는 뜻**이다.
픽업이 어려운 사용자에게는 사실상 구매 불가이며, 검증기가 경고로 잡는다.

### `options[]` 항목

| 필드 | 값 | 설명 |
| --- | --- | --- |
| `method` | `FREE` / `STANDARD` / `CONVENIENCE_STORE` / `UNKNOWN` | 정규화된 배송 수단 |
| `carrier` | `GS25` / `CU` / `null` | 택배사. 단정할 수 없으면 `null` |
| `requires_pickup_point` | bool | **편의점 등 픽업 장소 방문이 필요한가** |
| `fee` | int \| null | 배송비(원) |
| `remote_fee` | int \| null | 도서산간 추가 배송비. N플리마켓만 제공 |
| `raw_code` | any | 플랫폼 원본 코드 |

### 플랫폼별 매핑

| 플랫폼 | 원본 코드 | `method` | `carrier` | `requires_pickup_point` |
| --- | --- | --- | --- | --- |
| 번개장터 | `DEFAULT` | `STANDARD` | — | `false` |
| 번개장터 | `GS_HALF_PRICE` | `CONVENIENCE_STORE` | `GS25` | `true` |
| 번개장터 | `CU_THRIFTY` | `CONVENIENCE_STORE` | `CU` | `true` |
| 중고나라 | `deliveryType: 0` | `STANDARD` | — | `false` |
| 중고나라 | `deliveryType: 1` | `CONVENIENCE_STORE` | `CU` | `true` |
| 중고나라 | `deliveryType: 2` | `CONVENIENCE_STORE` | `GS25` | `true` |
| N플리마켓 | `DIRECT_DELIVERY` | `STANDARD` | — | `false` |
| N플리마켓 | `PICKUP_DELIVERY` | `CONVENIENCE_STORE` | — | `true` |
| 11번가 | `deliveryDescription: "무료"` | `FREE` | — | `false` |
| 11번가 | `deliveryDescription: "2,500원"` | `STANDARD` | — | `false` |

11번가는 오픈마켓이라 편의점 반값택배가 없다. 배송 수단은 일반 택배 하나뿐이고
`무료`면 판매자 부담(`SELLER`), 금액이 표시되면 구매자 부담(`BUYER`)이다.
표본 672건 중 `무료`가 603건으로 대부분이 무료배송이었다.
해석하지 못한 문자열은 0원으로 채우지 않고 `NOT_AVAILABLE`로 둔다.

중고나라 택배사는 세 값이 함께 나온 글에서 확정했다. 화면 표기와 금액이
정확히 대응한다([231559333](https://web.joongna.com/product/231559333)).

| 화면 표기 | 금액 | `deliveryType` |
| --- | --- | --- |
| 일반택배 | 5,000원 | `0` |
| CU 반값택배 | 2,700원 | `1` |
| GS 반값택배 | 2,800원 | `2` |

> N플리마켓 `PICKUP_DELIVERY`는 3,600원 정액이라 플랫폼 픽업 서비스로 판단했다.
> 화면 라벨로 확정하지는 못했다.

### 부담 주체 판정

| 플랫폼 | 판매자 부담(`SELLER`) | 구매자 부담(`BUYER`) |
| --- | --- | --- |
| 번개장터 | `trade.freeShipping == true` | `shippingSpecs.*.fee` |
| 중고나라 | `parcelFee == 1` | `deliveryInfos[].deliveryPrice` |
| N플리마켓 | `payerType == "SELLER"` | `payerType == "BUYER"` |

> **중고나라 `parcelFee`는 금액이 아니라 '배송비 포함 여부' 플래그다.**
> `1`이면 화면에 '배송비 포함·무료배송'으로 표시되고 `deliveryInfos`가 없다.
> `0`이면 `deliveryInfos`에 구매자가 낼 금액이 들어 있다.
>
> **번개장터는 무료배송일 때 `shippingSpecs`를 아예 내려주지 않는다.**
> specs 유무만 보면 무료배송이 '정보 없음'으로 잘못 처리되므로 플래그를 먼저 확인한다.

### 실제 데이터

**① 일반택배 + 편의점 택배 (번개장터)** — 판매가 250,000원

```json
{
  "status": "AVAILABLE",
  "payer": "BUYER",
  "min_fee": 2500,
  "home_delivery_fee": 5000,
  "options": [
    { "method": "STANDARD",          "carrier": null,   "requires_pickup_point": false,
      "fee": 5000, "remote_fee": null, "raw_code": "DEFAULT" },
    { "method": "CONVENIENCE_STORE", "carrier": "GS25", "requires_pickup_point": true,
      "fee": 2500, "remote_fee": null, "raw_code": "GS_HALF_PRICE" },
    { "method": "CONVENIENCE_STORE", "carrier": "CU",   "requires_pickup_point": true,
      "fee": 2500, "remote_fee": null, "raw_code": "CU_THRIFTY" }
  ],
  "raw": { "DEFAULT": {"fee":5000}, "GS_HALF_PRICE": {"fee":2500}, "CU_THRIFTY": {"fee":2500} }
}
```

편의점을 쓰면 총 252,500원, 못 쓰면 255,000원. **2,500원 차이가 난다.**

**② 무료배송 (판매자 부담)**

```json
{
  "status": "AVAILABLE",
  "payer": "SELLER",
  "min_fee": 0,
  "home_delivery_fee": 0,
  "options": [
    { "method": "FREE", "carrier": null, "requires_pickup_point": false,
      "fee": 0, "remote_fee": null, "raw_code": null }
  ],
  "raw": { "freeShipping": true }
}
```

**③ 직거래 전용**

```json
{
  "status": "NOT_AVAILABLE",
  "payer": null,
  "min_fee": null,
  "home_delivery_fee": null,
  "options": [],

```

## 5. 위치 `location`

### 구조

```jsonc
{
  "name": "서창동",                            // 대표 지역명(표시용)
  "full_address": "인천광역시 남동구 서창동",     // 지오코딩 입력용
  "precision": "FULL" | "DONG_ONLY" | "NONE",
  "regions": [ /* 거래 가능 지역 전체 */ ],
  "coordinates": null                          // 지오코딩 단계에서 채움
}
```

**세 플랫폼 모두 좌표를 제공하지 않는다.** 행정동 텍스트만 주므로
거리 계산에는 별도 지오코딩 단계가 필요하다. `coordinates`는 자리만 만들어 뒀다.

### `precision`

| 값 | 의미 |
| --- | --- |
| `FULL` | 시도·시군구·읍면동이 모두 있음 |
| `DONG_ONLY` | 동 이름만 있음. 동명이 전국에 여러 개일 수 있어 지오코딩이 모호함 |
| `NONE` | 위치 정보 없음 |

> **거리 점수를 매길 때 `precision`을 반드시 함께 읽어야 한다.**
> 무시하면 특정 플랫폼이 체계적으로 유리하거나 불리해진다.

### 플랫폼별 원본

| 플랫폼 | 원본 경로 | 형태 |
| --- | --- | --- |
| 번개장터 | `product.geo.address` | 전체 주소 문자열 |
| 중고나라 | `search.locationNames[]` | 전체 주소 문자열 |
| N플리마켓 | `saleProduct.saleProductRegions[]` | **동 이름 + 내부 지역코드** |
| 11번가 | 없음 | 직거래가 없어 `precision: NONE`, `regions: []` |

> 11번가 판매자 주소는 사업자 정보일 뿐 만나는 장소가 아니다. 거리 점수 계산에서
> 제외되어야 하므로 위치를 비워 둔다.

### N플리마켓 주소 보강

N플리마켓 상세 응답은 동 이름만 준다. 계층 주소 필드(`regionName1~3`)가
스키마에는 있으나 값이 전부 `$undefined`다.

함께 오는 `rcode`는 **네이버 자체 코드**로, 행안부 법정동코드가 아니다
(표준이라면 강남구가 `1168`인데 여기선 `0968`). 공개 데이터와 조인되지 않는다.

그래서 크롤러가 네이버 지도의 주소 조회 경로로 전체 주소를 따로 가져온다.

```
GET https://m.map.naver.com/search2/searchAddressById.naver?rcode=11200105
→ 302 Location: ...?query=인천광역시 남동구 서창동
```

`Location` 헤더만 읽으므로 본문을 받지 않는다(건당 약 0.12초). 같은 지역은 캐시한다.
조회 결과는 원본에 `resolvedFullAddress`로 붙고, **하나라도 실패하면 `DONG_ONLY`로 낮춘다.**

### 실제 데이터

**복수 거래 지역 (N플리마켓)** — 판매자가 최대 3곳까지 등록한다

```json
{
  "name": "서창동",
  "full_address": "인천광역시 남동구 서창동",
  "precision": "FULL",
  "regions": [
    { "name": "서창동", "full_address": "인천광역시 남동구 서창동", "code": "11200105" },
    { "name": "구월동", "full_address": "인천광역시 남동구 구월동", "code": "11200101" },
    { "name": "수산동", "full_address": "인천광역시 남동구 수산동", "code": "11200108" }
  ],
  "coordinates": null
}
```

> **거리 점수는 `regions` 중 가장 가까운 지역 기준으로 계산해야 한다.**
> 대표값(`name`·`full_address`)은 첫 번째 항목일 뿐이다.

**동명이인 해소 사례**

| 원본 | 보강 후 |
| --- | --- |
| `중동` | `부산광역시 해운대구 중동` |
| `좌동` | `부산광역시 해운대구 좌동` |
| `당하동` | `인천광역시 검단구 당하동` |
| `용원동` | `경상남도 창원시 진해구 용원동` |

### 실제 분포 (표본 40건)

| `precision` | 건수 | 비고 |
| --- | --- | --- |
| `FULL` | 29 | 번개장터 9 · 중고나라 11 · N플리마켓 9 |
| `NONE` | 11 | 원본에 지역 정보 자체가 없음 |
| `DONG_ONLY` | 0 | 주소 보강으로 해소됨 |

거래 지역 2곳 이상: 6건 (전부 N플리마켓)

## 6. 거래방식 `trade_method`

`PARCEL`(택배) / `MEET`(직거래)의 배열. 둘 다 가능하면 두 값이 모두 들어간다.

| 플랫폼 | 판정 근거 |
| --- | --- |
| 번개장터 | `trade.freeShipping` 또는 `trade.shippingSpecs` → `PARCEL` / `trade.inPerson` → `MEET` |
| 중고나라 | `tradeType.isPost` → `PARCEL` / `tradeType.isMeet` → `MEET` |
| N플리마켓 | `saleProductDeliveries` → `PARCEL` / `saleProductRegions` → `MEET` |
| 11번가 | 항상 `["PARCEL"]`. 오픈마켓이라 직거래 선택지가 없다 |

중고나라는 플랫폼이 명시한 값을 그대로 읽는다. 다른 두 곳처럼 배송·지역 정보
유무로 유추하는 것이 아니므로 신뢰도가 더 높다.

> 중고나라 `tradeType.isPickup`(편의점 픽업)은 통합 스키마에 대응 값이 없어
> 반영하지 않는다. 표본 15건 전부 `false`였다.

### 실제 분포 (표본 40건)

`MEET`+`PARCEL` 19 · `PARCEL` 11 · `MEET` 10

## 7. 검증 규칙

`validate_unified_schema.py`가 검사하는 항목이다.

**오류(errors)** — 스키마 위반

- 필수 문자열 필드 누락, `platform`·`condition_level`·`trade_method` enum 위반
- `price` 음수, `url`이 `http`로 시작하지 않음
- `delivery_fee.status == AVAILABLE`인데 `raw`가 `null`이거나 `options`가 빈 배열
- `delivery_fee.status == NOT_AVAILABLE`인데 `payer`가 존재
- **`min_fee`·`home_delivery_fee`가 `options`와 불일치**
- `location.precision == FULL`인데 `full_address`가 없는 지역이 존재
- `precision == NONE`인데 `regions`가 존재(또는 그 반대)

**경고(warnings)** — 확인이 필요한 상태

- `status == AVAILABLE`인데 `payer`를 특정하지 못함
- **편의점 픽업 외 배송 수단이 없음**(`home_delivery_fee == null`)
- `coordinates`가 변환 단계에서 채워짐(지오코딩은 별도 단계라는 전제 위반)

## 8. 알려진 한계

| 항목 | 내용 |
| --- | --- |
| `coordinates` | 항상 `null`. 거리 계산에는 별도 지오코딩 단계가 필요하다 |
| 판매자 신뢰도 | 스키마에 없다. 원본에는 번개장터만 별점·판매건수·가입일이 풍부하고 N플리마켓은 사실상 없어, 그대로 넣으면 플랫폼 간 비교가 불공정해진다 |
| 판매 상태 | 스키마에 없다. 크롤러가 수집 시점에 판매중만 거른다. 캐시가 오래되면 이미 팔린 상품이 남을 수 있다 |
| 등록일시 | 스키마에 없다. `collected_at`은 수집 시각이지 매물 등록 시각이 아니다 |
| 중복 상품 | 제거하지 않는다. 같은 판매자가 같은 상품을 여러 건 올리면 별개 항목이 된다. Top-K 단계에서 별도 툴로 처리한다 |
| 중고나라 `productCondition: 1` | 아직 관측되지 않았다. `UNSPECIFIED`로 두고 있으며 발견 시 재확인이 필요하다 |
| N플리마켓 5번째 상태값 | 등록 화면은 5단계인데 4개만 관측됐다. 미관측 값은 `UNKNOWN`으로 떨어진다 |
| 네이버 지도 주소 조회 | N플리마켓 API가 아닌 별도 경로다. 사이트 변경 시 여기만 깨질 수 있으며, 실패하면 `DONG_ONLY`로 안전하게 낮아진다 |
